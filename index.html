JurkOS

JurkOS is an independent, minimalist "On-the-Go" operating system targeting high-performance portability and bare-metal reliability. It is designed to be a lightweight, independent platform that prioritizes speed, efficiency, and a direct user-to-kernel relationship.

Project Target & Roadmap

The primary target of JurkOS is to provide a unified, persistent environment that remains consistent across different hardware architectures (HDD, SSD, and NVMe). Currently, the system supports 32-bit and 64-bit x86 architectures. Future updates will introduce ARM support to expand the ecosystem further.

Minimum System Requirements

  • Minimum CPU (32-bit): Intel Pentium Pro / Pentium II, AMD K6, or i686-class processor (with CMOV)
  • Minimum CPU (64-bit): x86-64-v1 compatible processor (Intel Core 2 / AMD Athlon 64 or newer)
  • RAM (Minimum): 40 MB – 50 MB (Recommended: 64 MB – 128 MB+)
  • Storage: 512 MB USB Flash Drive (Bootable)
  • Graphics: Standard VESA / Framebuffer Display Adapter
  • Firmware: Legacy BIOS (MBR) Support

WARNING: UEFI IS NON-SUPPORTED! JurkOS requires Legacy BIOS mode to boot.

While this is an early release and not all hardware is compatible yet, future updates (1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 1.9 Alpha) will focus on expanding hardware compatibility and feature sets.

The goal is for JurkOS to become a fully usable OS capable of reviving old computers, blending high-performance utility with lightweight efficiency and modern Linux 6.14 kernel capabilities.

This Alpha release serves as the foundation for a fully independent ecosystem, focusing on a specialized C-based kernel shell and deterministic storage management.

Wi-Fi Manager (wifi)

JurkOS features an integrated, high-speed terminal wireless manager. It allows you to scan for nearby Wi-Fi networks, connect instantly to open networks with zero password prompts, or authenticate with password-protected WPA/WPA2/WPA3 access points.

How to Launch

Simply type wifi from anywhere in the JurkOS shell: 

jurkos@jurkos:/$ wifi

Interactive Wi-Fi Controls

  • Network Selection ([1], [2], etc.): Type the number corresponding to the SSID you want to connect to and press Enter.
  • Open Networks: If the network has no password (Open/None), JurkOS connects immediately without asking for credentials.
  • Secured Networks (WPA2-PSK / WPA3-SAE): Prompts for the network password with privacy-masked asterisks (*).
  • Manual SSID (M): Connect to hidden access points by manually entering the SSID and security type.
  • Rescan (R): Refresh nearby access point list and signal strengths in real time.
  • Quit (Q): Return safely back to the JurkOS command prompt.

DHCP & Profile Persistence

Upon successful connection, JurkOS automatically initiates BusyBox udhcpc to acquire a dynamic IP lease, populates /etc/resolv.conf with DNS resolvers (Google 8.8.8.8 and Cloudflare 1.1.1.1), and saves your profile to /encrypted/wifi_history.conf so your wireless settings persist across boots.

JurkStore (TUI Edition)

JurkStore is the official terminal-based application store and package manager for JurkOS. Currently featured in a high-speed TUI (Terminal User Interface) mode for JurkOS, a full graphic API and desktop GUI version is scheduled for release in JurkOS 1.2.

Official GitHub Repository

All JurkStore applications are hosted directly in the official repository:
https://github.com/AmineTheJurk/JurkStore-Apps

How to Launch & Controls

To launch the store directly from anywhere in JurkOS, enter: 

JurkStore
  • Arrow Keys (↑ / ↓): Scroll and navigate up and down through the list of available apps.
  • Enter / Space: Open the selected app's detailed view, displaying its version, author, and description.
  • Key "i": Download and install the selected application directly to /usr/apps/[AppName]/.
  • Key "r": Live-refresh the catalog directly from the GitHub repository.
  • Key "q" or "b": Return back to the shell or previous menu.

Package & Repository Structure

Each app in the repository resides in apps/[app_name]/ and contains two essential components:

  1. meta.xml: The package metadata descriptor (name, version, author, description, download URL).
  2. [AppName].bk: The executable Linux binary (renamed with the .bk extension).

The Package Descriptor: meta.xml

The meta.xml file is the heartbeat of every JurkStore package. It defines all key metadata required by the package manager: 

<?xml version="1.0" encoding="UTF-8"?>
<jurkos-app>
    <name>MyApp</name>
    <version>1.0.0</version>
    <author>Exemple</author>
    <description>This Is My App - Official demonstration application for JurkStore</description>
    <download>https://raw.githubusercontent.com/AmineTheJurk/JurkStore-Apps/main/apps/exemple/MyApp.bk</download>
</jurkos-app>
  • <name>: The executable and display name. JurkStore creates a /bin/[name] system symlink upon install.
  • <version>: Semantic version tag of the release (e.g. 1.0.0).
  • <author>: App developer or maintainer name.
  • <description>: Concise summary displayed in the TUI browser when inspected.
  • <download>: Direct raw download URL to the executable binary.

How to Publish Your App

  1. Fork the Repository: Fork https://github.com/AmineTheJurk/JurkStore-Apps to your own account.
  2. Add Your Files: Create a folder in apps/[AppName]/ containing your meta.xml and [AppName].bk binary.
  3. Submit a Pull Request: Open a Pull Request from your fork back to the main repository.
  4. Administrator Review: Wait patiently while an administrator reviews your submission and accepts/merges your PR.
  5. Live Deployment: Once merged, the GitHub Action automatically updates catalog.txt, and your app becomes instantly available in JurkStore!

Installation Target & System Integration

When you press "i" in JurkStore:

  • The application directory is created at /usr/apps/[AppName]/.
  • The meta.xml file is saved locally to track package information.
  • The executable is extracted, given execute permissions (chmod +x), and linked to /bin/[AppName].
  • You can immediately run the application by typing its name (e.g. MyApp) directly in the JurkOS terminal!

Internal Architecture & Kernel Framework

JurkOS features its own custom, standalone kernel written from scratch in C and Assembly, designed for deterministic execution, high performance, and zero dependency on third-party kernel trees.

1. CPU & Memory Framework

The kernel establishes its own hardware foundation directly upon boot:

  • GDT & TSS: Sets up 64-bit Long Mode and 32-bit Protected Mode segments for kernel (Ring 0) and userland (Ring 3) code/data execution.
  • IDT & PIC Remapping: Configures a 256-entry Interrupt Descriptor Table, handling all 32 CPU exceptions and remapping hardware IRQs (PIT timer, PS/2 keyboard, and PCI interrupts).
  • 4-Level Paging (PML4) & PMM: Implements a physical memory page frame bitmap allocator and 4-level virtual memory translation with higher-half kernel mapping at 0xFFFFFFFF80000000.

2. Universal VFS Layer

JurkOS operates on a universal VFS layer supporting FAT32 and direct block storage:

  • Standard VFS Format: Clean inode mapping, directory indexing, and deterministic disk access.
  • Dynamic DevFS (/dev): Mounts a Linux-like virtual device hierarchy exposing hardware directly: /dev/fb0 (framebuffer), /dev/input/kbd0 (keyboard), /dev/net/eth0 (Intel e1000), /dev/pci/ (scanned PCI devices), and /dev/disk/.

3. Dual Executable Parsers (ELF & XEC) with .JEX Support

JurkOS features an in-kernel dual binary dispatcher:

  • Standard ELF-64 / ELF-32: Parses ELF program headers (PT_LOAD), maps virtual segments, zeroes .bss, and allocates user stacks.
  • XEC Flat Binaries: Executes raw, stripped machine code images directly at base user virtual addresses.
  • Official .JEX Package Extension: Any application package with the .jex extension is automatically probed and executed as either ELF or XEC seamlessly.

4. Minimal Hardware I/O Pipeline

  • VESA / GOP Framebuffer: Direct linear pixel rendering with an embedded 8x16 font, smooth terminal scrolling, and ANSI color box rendering.
  • Intel e1000 Driver: Native DMA ring driver for the widely emulated Intel 82540EM / 82545EM Gigabit Ethernet adapter.
  • PS/2 Keyboard & Serial: Full QWERTY scancode mapping with input queuing and COM1 UART debug output.

How to Compile

This document explains how to build the custom JurkOS kernel and package the disk image.

1. Install Required Tools

Before building, ensure your environment has the required toolchain installed:

sudo apt update && sudo apt install -y build-essential gcc-multilib binutils limine zip gzip dosfstools mtools parted

2. Compiling Kernel

Compile the 64-bit and 32-bit standalone JurkOS kernels:

cd source/kernel && make kernel-x86_64.elf && make kernel-x86.elf && cd ../.. && echo "Compiling Kernel complete."

3. Compiling JurkOS

Compile userland binaries from NoneCompiled/ and assemble the disk image:

make -C source/bearssl -j4 && mkdir -p lib && cp -f source/bearssl/build/libbearssl.a lib/libbearssl.a && gcc -static -O2 NoneCompiled/wget.c lib/libbearssl.a -Isource -o iso/bin/wget && truncate -s 128M jurkos.img && parted -s jurkos.img mklabel msdos mkpart primary fat32 1MiB 100% set 1 boot on && mformat -i jurkos.img@@1M -F -v "JURKOS" && mcopy -o -s -i jurkos.img@@1M iso/* ::/ && limine bios-install jurkos.img

4. Flash to USB

Once the build is complete, use ImageUSB or USBImager to flash jurkos.img to your physical USB drive.

How to Flash

Flashing JurkOS correctly is essential to maintain the read-write persistence of the operating system. Standard ISO burners (like Rufus in ISO mode) may mount the drive as read-only, which will break JurkOS functionality.

Recommended Tool: ImageUSB

We highly recommend using ImageUSB by PassMark Software. ImageUSB is great for this type of project shout out to passmark software to making this great tool of my needs.

Steps to Flash:

  • Download and run ImageUSB.
  • Select your target USB drive from the list.
  • Select the 'Write image to USB drive' action.
  • Browse and select your compiled jurkos.img.
  • Click 'Write' and wait for the process to complete.

Once finished, your USB will have the exact same filesystem and partition structure as the image, ensuring it remains fully writeable and ready to boot.

Running in a VM (QEMU)

You can test JurkOS in a Virtual Machine before booting on bare metal. We recommend using QEMU for its powerful hardware emulation and serial redirection capabilities.

⚠️ Wi-Fi on a VM (QEMU) is NOT Supported

Virtual Machines (QEMU, VirtualBox, VMware) only emulate a virtual wired Ethernet card (e1000 or virtio-net). They do NOT expose host Wi-Fi antennas as a 802.11 wireless device to guest operating systems.

To use wireless Wi-Fi scanning with wifi, boot JurkOS directly on physical hardware (USB drive) or pass through a USB Wi-Fi dongle into QEMU. Inside QEMU, JurkOS connects automatically using the virtual wired Ethernet connection!

Testing with Physical USB

To boot JurkOS in QEMU using your actual flash drive (while maintaining persistence), follow these steps on Windows:

1. Identify your USB Drive

Open CMD as Administrator and run:

wmic diskdrive list brief

Look for your USB and note the DeviceID (e.g., \\.\PhysicalDrive1).

2. Launch QEMU

Run the following command to boot your physical flash drive as a genuine USB device (update PhysicalDrive1 to your drive number, run CMD as Administrator):

qemu-system-x86_64 -accel whpx -cpu host -smp 1 -m 512M -device qemu-xhci -device usb-storage,drive=usbdrive -drive if=none,id=usbdrive,format=raw,file=\\.\PhysicalDrive1,cache=unsafe -netdev user,id=net0 -device e1000,netdev=net0 -vga std -serial stdio

Key Features & Flags Explained:

  • -accel whpx: Uses Windows Hypervisor Platform hardware virtualization for near bare-metal speed.
  • -cpu host: Passes your actual host processor features into the virtual machine.
  • -smp 1: Allocates 1 CPU core to the virtual machine.
  • -m 512M: Allocates 512 MB of physical RAM to the virtual machine.
  • -device qemu-xhci: Emulates a high-speed USB 3.0 XHCI controller.
  • -device usb-storage,drive=usbdrive: Mounts the storage as a real USB flash drive rather than a slow legacy IDE hard disk.
  • -drive if=none,id=usbdrive,format=raw,file=\\.\PhysicalDrive1,cache=unsafe: Connects physical USB Drive 1 with write-back caching for fast, persistent storage.
  • -netdev user,id=net0: Enables SLIRP user-mode network stack for internet connectivity.
  • -device e1000,netdev=net0: Emulates an Intel e1000 Gigabit network interface card for internet connectivity.
  • -vga std: Sets standard VESA VGA display adapter for GUI/framebuffer compatibility.
  • -serial stdio: Redirects the kernel serial console directly to your terminal window so you can view kernel logs and interact with the shell.

Common Problems

Hey Dude this project is cool but the qemu command you gave me dosent work on linux...

Thats Ok! Use This Command instead! : 

sudo qemu-system-x86_64 -enable-kvm -cpu host -smp 1 -m 512M -device qemu-xhci -device usb-storage,drive=usbdrive -drive if=none,id=usbdrive,format=raw,file=/dev/disk/by-id/mbr-0x12345678,cache=unsafe -netdev user,id=net0 -device e1000,netdev=net0 -vga std -serial stdio

What Do I Do I Am On Linux Not Windows!

If you are using Linux and cannot use ImageUSB, we recommend using USBImager. It is a lightweight, open-source tool that performs reliable bit-for-bit flashing and is available for Linux, Windows, and macOS.

You can find it here: USBImager on GitLab.

I dont have hypervision!

If your computer does not support hardware virtualization or WHPX is not enabled, use this command with -cpu max: 

qemu-system-x86_64 -cpu max -smp 1 -m 512M -device qemu-xhci -device usb-storage,drive=usbdrive -drive if=none,id=usbdrive,format=raw,file=\\.\PhysicalDrive1,cache=unsafe -netdev user,id=net0 -device e1000,netdev=net0 -vga std -serial stdio
